## 会改变结果解读的发现

- **健身直觉型的 6/6 不能由记录全部支持。** Lotus Room 的两节课、Blue Moon 定位、Fight Girl 课程有实际页面内容；但没有核实 Mandala 的课表，Blue Moon 门店来自搜索摘要，Fight Girl 报名流程没有打开。按原标准逐项核对为 2 项支持、1 项不满足、3 项证据不足。
- **医院两个 3/7 均有多给分。** 实际没有创建 CryptPad 文档；不能把聊天中的十个名字视为完成了文档中的十项要求。完整十家质量声明也没有逐项来源支持。各自只有候选来源 R1 有明确支持，另有 5 项不满足、1 项证据不足。
- **两次医生任务的 0/6 与操作记录一致。** 委托型声称已验证十人、已打开十个简介，实际只有搜索页和错误路径，也没有电子表格。核查型承认未完成，但不能把 404 路径笼统解释成所有来源都被阻拦。
- **普拉提两次 R2 也存在少给分。** 原始任务允许 Fresno 或 Clovis 周边至少三家。CORE、Club Pilates Clovis、Pilates Street 已达到这项最低要求；没有要求额外再找三家 Fresno 工作室。与此同时，细节型把 CORE 内容错归 Title 29，精简型把 Title 29 的营业时间当课时，不能保留这些成功声明。
- **视频任务的‘已打开／已播放’与标签页不符。** 直觉型只打开晨练视频，Vinyasa 仍是搜索页；分析型没有任何视频播放页，其晨练链接还对应到已读搜索结果中的 45 分钟视频。两份计划结构完整不代表链接与播放动作已经完成。

## P1–P5 和 persona 分数该怎么读

P1–P5 是 PersonaCUABench 的扩展体验评价，不是 Odyssey 原任务 rubric。两个模型评价可能一致地依赖错误前提，不能用相互一致代替证据核查。

例如 YouTube 直觉型的评价 a 给 P1/P3/P5 都打了 5，理由称两个视频均已打开；最终标签页却只有一个视频页。评价 b 的 P3=5 也重复此错误。健身分析型的评价认为‘其他场所已总结且页面保留’，但本次运行根本没有访问 Blue Moon 和 Fight Girl。这些理由需要重评，不能继续用高可执行性或高满意度分证明实际完成。

可读性 P2 与任务完成度是不同维度。清楚的失败说明仍可能可读；0/6 不数学地强制 P5=1。本次只标注理由是否有依据，没有凭直觉改写主观分数。

## 与原 Odyssey 是否一致

从上游固定提交 `837814633ef948479abb3d142458f0acdb73fa65` 的 Git 对象重新取出任务数据，确认本地 6 个 task、33 个 rubric、13 份完整运行快照及 4 份失败尝试快照均逐对象一致。12 次开场保留原任务全文，只在末尾添加偏好。

一致的是任务和 rubric 文本，不是整个实验协议。本 pilot 的保存配置为本地 Chrome／Playwright、Bedrock gpt-oss-120b、50 步、低 reasoning；原 Odyssey 的 OSWorld 环境、执行与截图评审流程不同。Persona 表达和 P1–P5 也是额外评价。因此这些分数不能直接当作官方 Odyssey 结果或用于其排行榜比较。

## 失败尝试与证据边界

共 17 次尝试：12 次有最终回答；另有 4 次浏览器停滞和 1 次 API 超时。后五次继续单独保留为未评分，没有补成 0 分，也未从尝试总数移除。健身分析型的最终回答来自单独保存的超时重试。

保存的证据是文本工具轨迹及最终标签页，不是截图或录像。部分网页文字被截断，因此某条事实未出现在摘录中不必然等于现实中不存在。判断‘未创建文档／未打开指定视频’使用的是本次完整动作目录与最终标签页；对内容身份、报名细节或质量声明不能充分确认的部分，保留为证据不足。

没有用今天的网站内容补写运行当天的证据，也没有重新核实任何现实医院、医生或健身服务。原文件 SHA256 已在写入前后核对一致；所有 66 条 rubric、step 引用、摘录字符范围和来源 JSON 位置均通过机械校验。
